# 社区发布项目中的 Google Cloud 集成

我创办 AI 造物社区，与女性、青少年和跨学科创作者一起做 AI、智能硬件和机器人项目。
除了工作坊和项目指导，我也持续把技术研究、现场讨论与项目经验整理成内容。
线上发布基础设施让这些工作不只停留在一次活动里，也方便之后继续阅读和交流。

随着内容服务展开，我需要考虑页面怎样稳定交付、静态内容与后端怎样分工，以及
数据如何持久保存。我使用 Firebase Hosting 分发静态内容，Cloud Run 承接容器化
服务，Firestore 保存需要持久化的数据。这些服务各自承担不同职责，也可以独立维护。

云端接入带来了比业务功能更通用的问题：运行程序使用哪个项目和身份，构建镜像的
账号是否也需要运行权限，秘密配置应该在哪一步注入，以及一次重试怎样避免覆盖
已经存在的数据。Cloud Build、Artifact Registry、IAM 和 Secret Manager 分别
进入了这条交付链路。

本仓库把这些集成方式整理成模块与配置参考：Firestore 的通用文档读写、显式 ADC
配置、Hosting 缓存和转发，以及构建身份和运行身份的分工。社区应用代码和内容不在
公开范围里，接入方使用自己的应用与数据模型。

它与 Strategic Signal Scanner 分别对应内容工作的前后两段：Scanner 帮我整理
研究候选，我负责选题与编辑，再通过发布基础设施交付内容。这段实际工作是两个
项目的共同起点。公开材料着重说明其中可独立理解的 Google Cloud 技术选择。

实现与集成方式见 [Google Cloud 工程案例](GOOGLE_CLOUD_CASE_STUDY.md)及
[技术指南](TECHNICAL_GUIDE.md)。
